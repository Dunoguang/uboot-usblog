# 2026-09-26 findings + new images

All of this was verified on a DW99 (SL8541E) watch with the unlocked uboot
image `images/uboot.img` (md5 a03efc263613a61680e892261df90954,
sha256 b8ec59c9cb19c17564d704e5cc4bcf543495e7af8bef61467bdb14240de9092a).

## 1. Root cause: why v1..v25 never produced a single byte

The u-boot gserial ("Gadget Serial") path waits for the tool to open the
port.  Without a tool handshake it prints

    usb calibrate port open timeout3871,1870,2000

and continues **without allocating the 8 KB gserial channel buffer**: the
`bl 0x9F02CDFC` at file 0x1A558 sits on the "port opened" branch and is
skipped on the timeout path.  With no channel, `reply_to_pctool` writes into
a ring that is never wired to the endpoint, so no host-side reader can ever
receive anything.  Host side the reads simply time out (libusb rc=-7) until
the gadget disappears.

## 2. Working configuration (verified: real bytes captured)

Device image: `images/uboot-v26-forceport.img`
(md5 9a1d5975d299363045fbc702aa3e8fcd)
Host tool:    `tools/usb_reader.py`

Device side, two parts, both required:

  a) console hook.  file 0xE798 (puts entry) -> hook code placed in a
     never-called function body at 0x1BC34..; the hook calls a log fn that
     sends through reply_to_pctool (0x1A8BC).  The log fn is gated by a byte
     at 0x1BC34 (value 0 in the image); the gate is set at file 0x1A768,
     the printf call site of "USB SERIAL PORT OPENED".

  b) force the 8 KB channel allocation: file 0x1A720
     (`cbnz w0,+0x38`) -> `b +0x38`.

Captured with `tools/usb_reader.py` (258 bytes on bulk EP5-IN 0x85):

    USB SERIAL PORT OPENED
    usb read timeout
    ** File not found /recovery/last_memory **
    lcd start init time:12148ms
    sprd backlight power brightness=0
    phy status0 1f00
    phy status 1f00
    phy status1 1f00
    phy status2 1f1a
    sprdfb: mipi_dispc_init_config not support TE

Known issue of v26: taking the "port opened" branch also runs the tool
handshake waits (the `usb read timeout` line), which adds about 8 seconds;
the LCD init is stretched to 12.1 s and the boot then stalls at the panel
read ID step.  `images/uboot-v27-alloc.img` and
`images/uboot-v28-alloc-fast.img` try to get the channel without those
extra handshake waits (not tested yet).

## 3. [0x30] must not be touched - the mechanism

The u-boot vboot code reads the image tail:

    sprd_get_vboot_key(): sechdr_offset is 0x760f0.
    sprd_get_vboot_key(): sechdr_addr is 0x9f075ef0.
    sprd_get_vboot_key(): sechdr_offset is 0x760f0, sechdr_addr->cert_offset is 0x76150.

The sechdr offset is derived from [0x30] (+0x200).  Changing [0x30]
(v13: 0x75EF0 -> 0x75FA4) makes vboot read the wrong location and the boot
enters a reset loop.  This is the "3.3 s reboot loop" symptom and the reason
every earlier image that modified [0x30] (v4/v5/v7/v12/v13) looped.  Note
the LCD init (`lcd start init time`) happens before the vboot step, which
matches "screen lights up, then it loops".

## 4. uboot_log partition: a complete offline log per boot

`uboot_log` = `/dev/block/mmcblk0p11`, 4 MB = header + N x 256 KB slots.
Each slot holds the complete pre-kernel u-boot console log of one boot.  It
is written at the very end of the u-boot run, so a boot that dies earlier
leaves no slot - but every boot that reaches the kernel jump (including
boots where the kernel itself then fails) does get one.

Reading it (watch in recovery, adb root; no patching needed at all):

    ./tools/dump_uboot_log.sh <adb-serial> <outdir>
    # manually:
    B=/dev/block/platform/soc/soc:ap-ahb/20600000.sdio/by-name
    adb -s <serial> shell dd if=$B/uboot_log of=/tmp/uboot_log.bin bs=4096
    adb -s <serial> pull /tmp/uboot_log.bin uboot_log.bin
    python3 tools/parse_uboot_log.py uboot_log.bin

Lines worth watching (from a normal boot):

    check_reboot_mode:get raw rst_mode is 40 ...   (reset came from PC tool)
    check_reboot_mode:get raw rst_mode is 0  ...   (normal power-on)
    is_7s_reset 0x1000, systemdump 0x0
    musb-hdrc: peripheral reset irq lost!
    USB SERIAL CONFIGED
    usb calibrate port open timeout3871,1870,2000
    battery unconnected shutdown charge!!!!!       (no battery -> charge logic)
